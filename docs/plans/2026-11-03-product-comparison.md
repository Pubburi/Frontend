## 범위·선행·구현 기준

- 공개 `GET /api/products/{id}`의 기존 Product7과 `GET /api/products/{id}/features`를 그대로 소비한다. ApiResponse·`credentials: include`·상품/특성 계약은 변경하지 않는다. 선택한 ID만 조회하며 상품 가격/도수/주종을 태그·용량으로 추정하지 않는다.
- 가격·도수의 실제 0, 특성 null의 미확인, 검수한 빈 태그 []의 등록된 태그 없음을 구분한다. 쉼표/내부 개행·Unicode 태그는 그대로 표시하며 기존 안전한 출처 링크 검사를 사용한다. 비교는 현재 공개 정보이며 주문 당시 스냅샷·재고·판매 SKU·추천 점수/구매 확인을 만들지 않는다.
- F06의 웹 구현·fixture·선택한 실제 서버 결과·최신 head 리뷰/CI·main 인계는 각각 구분한다. 필수 완료 3/20의 변경과 F06 최종 완료는 조정자가 인수 근거·병합/main 확인 뒤 판정한다. 전체 F02/FE03/C04·DB 전환이나 전체 20개 완료를 앞당겨 체크하지 않는다.

## 입력·상태·오류 소유

- 비교 URL은 최대 4개의 중복 없는 양의 정수 ID만 허용한다. 빈 값·선행 0·지수/소수·공백/마지막 개행·안전 정수 초과·중복·과다 선택은 주소 전체를 오류로 처리하고 상품 GET을 하지 않는다. 임의 절삭/숫자 강제 변환·부분 선택으로 바꾸지 않으며 전체 해제 후 다시 선택하는 동작을 제공한다.
- 목록·상세 버튼은 현재 선택 여부를 `aria-pressed`로 표시하고 한도 초과 시 기존 네 개를 보존한다. 비교 선택은 상품 필터 URL·검색 초안·세션·기존 장바구니 Product7/수량과 독립이다.
- 비교 화면 진입은 ID별 Query key로 현재 상품을 다시 읽고 그 성공 뒤 특성을 읽는다. 진행/연결 대기·현재 실패 중에는 캐시의 과거 값을 현재 조회 성공으로 표시하지 않는다. 응답의 상품/특성 ID도 요청 ID와 같아야 한다.
- 한 상품의 pending·404·503과 특성 조회 실패는 다른 열이나 해당 상품의 유효한 기본 정보를 가리지 않는다. 실패한 상품/특성의 명시 재시도·항목 제거·전체 해제를 제공한다. null 미확인과 조회 실패는 다른 상태다.
- 제거/새 URL/이탈 뒤 늦은 이전 성공·오류는 현재 선택이나 초안을 바꾸지 않는다. 읽기 응답 완료로 포커스를 이동하지 않는다. 키보드 제거/전체 해제의 현재 버튼이 집중돼 있을 때만 동기적으로 지속 제목에 포커스를 연결한다.
- 표의 행/열 제목·caption과 접근 이름을 제공한다. 좁은 웹은 문서 전체를 넓히지 않고 이름 있는 표 영역을 좌우로 스크롤하며 Tab/Enter 제거를 지원한다. 전체 보조기술/브라우저 조합 완료를 주장하지 않는다.

- 목록·상세 선택과 필터 URL/장바구니 보존, 현재 상품 가격 별도 조회·리터럴 태그와 안전한 출처.
- 네 개 선택/다섯 번째 거절·다시 선택, 직접 URL/새로고침/뒤로·제거/전체 해제와 무조회 빈 상태.
