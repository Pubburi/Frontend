# F02 가격·도수 범위의 공개 상품 검색 연결

## 범위·기준

- 기준 main은 `afa4a7d`다. 기존 공개 상품 목록에 원화 가격·도수의 최소/최대 네 입력을 연결한다. [Backend 상품 검색 계약](https://github.com/Pubburi/Backend/blob/main/docs/PRODUCT-SEARCH.md)의 기존 GET `/api/products`와 ApiResponse·Product 일곱 필드·PageResponse를 소비한다.
- 이번은 새 소비자 기능이다. 기준 웹의 입력 부재/범위 URL 미소비를 과거 장애나 오류율·시간 성능 개선으로 기록하지 않는다. 맛/향의 반복 태그 입력·OpenSearch·자동완성·전체 F02와 FE03/C04 인수는 미완료다.
- 기존 주종/검색어·정렬·장바구니/세션·공개 특성 및 페이지 이동의 적용 조건/미제출 초안 분리를 유지한다. API 제공자·DB·원본 상품/계정은 변경하지 않는다.

## 입력·적용 의미

가격은 포함하는 원화 범위의0..2,147,483,647 정수다. 도수는 포함하는0..100% 범위이며 입력 파라미터의 소수점 아래 최대 두 자리를 허용한다. 원래 상품의 도수를 반올림하거나 저장형의 정밀도를 바꾸지 않는다. 네 범위와 기존 주종/검색어는 모두 함께 만족해야 한다.

빈 폼 입력은 해당 경계 미지정이며 실제 `0`과 구분한다. 숫자 문자열을 검증 전에 `Number()`로 바꾸지 않아 지수/부호/16진수/공백·비ASCII 숫자/과도한 소수 자리와 역전 범위를 거절한다. 초과 길이의 붙여넣기도 자르지 않아 다른 유효 가격/도수로 바꾸지 않는다. 입력은 그대로 남기고 `aria-invalid`·연결한 오류 설명과 첫 오류 포커스로 수정할 수 있게 한다. 단순 number 입력에 맡기는 대안은 브라우저의 값 정리/지수 허용과 제공자 문법이 달라 선택하지 않았다.

직접 URL에 명시한 빈 값·잘못된 문법/범위·중복 경계는 상품 GET을 실행하지 않고 조건 수정/전체 해제를 안내한다. 중복 query를 마지막 값으로 조용히 축약하거나 잘못된 필수 조건을 지워 무제약 상품을 보이지 않는다. 사용자가 빈 폼을 명시적으로 검색하거나 전체 해제하는 동작은 무제약의 새 요청이다.

검색하기/Enter는 새 입력을 첫 페이지에 적용한다. 이전/다음은 현재 URL의 적용 조건을 사용하고, URL 변경/뒤로 가기/새로고침은 해당 입력을 복원한다. 기존 초안 칩/전체 해제는 유지하며 **현재 적용 범위**는 별도로 URL에서 표시해 편집 중에도 실제 결과 조건을 확인한다. Query key에 네 원문 값이 포함돼 이전 범위의 늦은 응답은 새 결과를 덮지 않는다.

## 사전 고정·검증

제품 소스를 바꾸기 전에 기준100개 프로덕션 파일/소스·README와 직접 작성한 시나리오를 SHA-256으로 고정했다. 기존 프로덕션 웹에 같은 새 입력 시나리오를 먼저 실행해 최소 가격 컨트롤이 없음을 확인했다. 기능 미제공 관측이며 제품 결함 감소의 분모가 아니다.

```bash
npm run typecheck
npm run test -- src/productRanges.test.ts src/utils/productFilters.test.js
VITE_API_BASE_URL=/api npm run build
npm run test:browser -- product-ranges.spec.js
npm run check
```

선택 단위 검증은 원문/실제0·빈 값, 제공자와 같은 가격/도수 문법/최대값, 직접 URL의 빈/중복 경계, 역전 범위와 페이지 직렬화를 다룬다. 프로덕션 Chromium은 다음 사용자 결과를 확인한다.

- 네 경계가 모두 API에 전달되고 하한/상한 상품은 포함하며 범위 밖 상품은 제외한다.
- 실제0 URL 복원·새로고침과 미제출 초안/적용 범위의 구분, 잘못된 입력의 보존·오류 포커스.
- 빈/잘못된/중복/역전 직접 URL의 무조회와 명시적 전체 해제 복구.
- 페이지 이동의 현재 조건, Enter 첫 페이지·뒤로 가기/초기화, 이전 범위 보류 응답의 격리와503 명시 재시도.
- 390px 웹의 단위/레이블·Tab/Enter와 가로 너비.

직접 작성한 상품/범위 fixture는 실제 주류·추천 학습 자료나 Backend E2E가 아니다. 실제 서버의 선택한 연결 관측과 fixture를 합산하지 않고 정확성/기능 제공을 자연 오류율·시간 성능으로 바꾸지 않는다.

선택 단위6개·최종 새 프로덕션 Chromium15개가 통과했다. 첫 선택 실행의 뒤로 가기 검증은 Enter 뒤 URL만 확인하고 새 결과/적용 범위가 그려지기 전에 뒤로 이동했다. 그 실패와 원 시나리오를 보존하고 새 첫 페이지 결과/적용 범위를 먼저 확인하도록 준비 경계를 보완했다. 제품 코드/프로덕션 파일이나 timeout을 바꾸지 않은 같은 웹으로 해당 준비를 확인했다. 390px에서는 잘못된 소수 입력의 오류 설명 연결/포커스와 수정 뒤 Tab/Enter도 확인한다. 이 준비 보완을 제품 결함 감소로 기록하지 않는다.

첫 전체 검사는 보존용 브라우저 시나리오 사본을 단위 runner가 수집해 중단됐다. 사본 내용을 보존하고 실행하지 않는 문서 확장자로 옮긴 뒤 제품/검사 설정을 바꾸지 않고 같은 전체 검사를 다시 실행했다. 준비 실패를 필수 검사 성공이나 제품 결함으로 집계하지 않는다.

Node **24.22.1**의 최종 `npm run check`는 저장소 검사·locked 설치·audit 취약점 **0**·이미지 도구·strict TypeScript·단위 **80개**·프로덕션 빌드·Chromium **216개**를 통과했다. 최종100개 프로덕션 파일과 소스/시나리오를 SHA-256으로 동결하고 검사 뒤 같은 byte임을 확인했다. 자체 preview는 종료했고 기존 사용자 프로세스를 변경하지 않았다.

## 별도 실제 서버·인계

같은 불변 legacy Backend jar(SHA-256 `dcb73c35b4dbf148b05775992408b8d930977e84022fbabc878e68491ed22b81`), 같은80개 시연 상품의 폐기 MySQL·고정 Recommendation B0와 기준/후보 프로덕션 웹을 연결했다. 두 웹에 같은1280px Chromium·읽기 전용 하네스(SHA-256 `51c26e0527ec4c1b041ffaa66f527bc04eb5ceff8098db62d6d4ba55c7f3863e`)를 적용했다. 원본/공유 DB와 기존 사용자 프로세스는 사용하지 않았다.

| 실제 관측 | 기준 웹 | 후보 웹 |
|---|---|---|
| 직접 URL의6,000..12,000원·0..15% | 네 입력 없음. 범위 없는 요청으로 전체80개 | 네 입력 복원·네 query 소비. 포함 범위를 모두 만족한 총6개 |
| 서버의 독립 범위 GET 기준 | 총6개·ID5/15/61/10/25/13 | 브라우저가 받은 총수/ID가 같은 기준과 일치하고 카드6개 표시 |

기준의 기능 부재→후보의 소비 제공이며 오류율/성능 감소로 계산하지 않는다. 후보에서 최대 가격을6,000으로 편집만 해도 적용 범위는12,000과 기존 결과를 유지하고 요청하지 않았다. 명시 제출한6,000..6,000원·0..15%는 실제 독립 GET과 같은0개였고, 전체 해제는80개로 복귀했다. 중복 최소 가격 URL은 상품 GET0건으로 조건 확인을 안내했다. 이 관측과 fixture15개를 합산하지 않는다.

예상하지 않은 API 오류·pageerror·응답 대체·업무 쓰기는 없었다. 조정자가 시작한 프로세스만 종료했고, 이번 소비 연결을 JPA 전체 전환·태그/검색 엔진·전체 F02/FE03/C04나 시간 성능 인수로 확장하지 않는다.

최신 PR/CI·완료 Codex 리뷰·미해결 대화·Squash/main CI·브랜치 정리는 조정자가 확인한다. 비공개 기획 주소·개인 경로·자격정보·원문 로컬 로그는 공개 문서/PR에 넣지 않는다.

## README 사례 판단

기존 계약의 명시 범위를 고객이 입력하고 확인할 수 있게 한 새 기능이며 과거 제품 장애의 독립적인 원인/수정 근거는 아니다. 기존 주문/다음 입력 소유, 최신 응답, 파괴적 작업의 DOM 포커스, 인증 캐시/진행 중 HTTP보다 더 강한 채용 사례의 영향을 입증하지 못했다. README의 현재 기능 한 행만 갱신하고 네 사례/순서·코드를 보존하며 [선정 기록](../case-study-register.md)에 이유를 남긴다. 테스트 수/CI 집계나 검증하지 않은 성능을 README에 추가하지 않는다.
