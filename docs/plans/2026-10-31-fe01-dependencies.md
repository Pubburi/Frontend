# FE01: Vue 웹 의존성 보안

- 기준: main 82c78b9, Node 24, npm lockfile 기반 설치.
- 변경 전: npm audit 총 14건(높음 8, 보통 6). 취약 패키지 그래프 수이며 실제 공격 가능성이나 앱 성능 수치가 아니다.
- 범위: Vue·Vite 6·Vitest·sharp의 수정 버전과 필요한 전이 의존성 갱신. 현재 Vue 기능·정적 자산·API/세션·기존 테스트를 유지한다. React 전환은 이 PR에서 구현하지 않는다.
- 방법: 공식 보안 권고·배포 메타·peer/Node 호환성을 확인하고 명시적으로 갱신한다. 강제 audit fix나 근거 없는 전이 패키지 override는 사용하지 않는다.
- 검증: npm ci, 기존 Vue 테스트, 프로덕션 빌드, 전체/운영 의존성 audit, 이미지 인코더 호환성, 실제 로컬 웹/API 프록시 실행. 최신 CI와 Codex 리뷰 후에만 병합한다.
- 성능: 보안·호환성 변경이므로 성능 개선을 주장하지 않는다. 테스트 개수와 audit 감소를 앱 응답 시간 개선으로 바꾸지 않는다.
- 상태: 로컬 구현·검증 완료. PR·CI·최신 Codex 리뷰 후 main 반영은 별도로 확인한다.

## 구현·검증 결과

- Vue 3.5.44, Vite 6.4.5, Vitest 4.1.12, sharp 0.35.5로 갱신했다. 미사용 Vue Test Utils와 그 전이 경로를 제거했다. 테스트 소스·화면·정적 자산·API 코드는 유지했다.
- 전체/운영 audit 모두 0개다. lockfile의 알려진 권고 검사 결과이며 공격 가능성이나 앱 성능의 개선 수치가 아니다.
- 로컬 Node 24에서 npm ci·보안 검사·기존 20개 테스트·PNG/방향 있는 JPEG의 실제 이미지 스크립트·프로덕션 빌드가 통과했다.
- 실제 MySQL·Backend·추천 health·웹 프록시 통합 기동, 브라우저 홈·80개 상품 목록·검색 1개 결과·상세 이동을 확인했다. 콘솔 오류는 없었다. 앱 종료와 DB 볼륨 보존도 확인했다.
- npm 11.5.2의 lock 생성 peer 해석 오류는 격리 npm 12.2.1 생성으로 해결했다. 전역 npm은 변경하지 않았고, 생성된 lock의 npm 11.5.2 설치·검증 성공을 확인했다.
- CI에 audit:deps(보통 이상 실패)와 check:images를 추가했다. 이미지 검증은 폐기 가능한 임시 자산만 사용한다.
