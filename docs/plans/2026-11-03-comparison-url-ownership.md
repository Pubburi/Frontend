# F06 — 빠른 뒤로 이동과 비교 선택의 URL 소유

## 관측과 범위

기준 main `88b8833`의 비교 화면은 상품을 해제하는 순간 공유 선택을 먼저 바꾸고 URL의 React 전환을 요청했다. 전환이 화면에 반영되기 전에 Back하면 URL/표는 원래 두 상품으로 돌아와도 메뉴와 목록의 공유 선택은 한 상품에 남을 수 있었다. F09 인수 중 원래 비교 회귀에서 표2개/메뉴1개를 관측했고, F09 제품 코드와 분리한 필수 F06 정합성 수정으로 처리한다. F09 계정 수정·데이터베이스/API·필수 기능 수를 이 PR에 추가하지 않는다.

최초 관측의 테스트는 URL 변경과 지속 제목의 포커스만 확인하고 약6ms 뒤 Back했다. 두 확인은 중간 한 열 화면의 commit을 보장하지 않는다. 정상 Back 대조는 해제된 한 열과 메뉴를 먼저 확인하도록 명확히 하고, 빠른 Back을 별도 회귀로 추가한다. 기존 테스트만 늦춰 결함을 숨기지 않는다.

## 원인과 최소 수정

`ComparePage.select`의 즉시 `replace(next)`는 아직 반영되지 않은 URL 전환과 별도의 공유 상태를 만들었다. 중간 전환이 취소되면 원래 URL의 effect dependency가 바뀌지 않아 그 effect가 이 값을 다시 덮지 않았다. 동일한 URL을 표시하는 표와 메뉴/목록이 다른 선택을 소유하는 원인이다.

선택/전체 해제는 URL 변경만 요청한다. 기존 effect가 실제 반영된 유효 URL에서 공유 ID를 갱신하도록 해 권위를 하나로 둔다. query를 새로 만들거나 모든 렌더에서 store를 덮는 대안은 사용하지 않았다. 반복 URL 순서·최대4·잘못된 주소의 무조회·기존 읽기/키보드 포커스·ID 전용 메모리·원문 장바구니는 유지한다.

## 수정 전후 검증

제품 수정 전에 원래 main의 production을 동결했다. API fixture와 별도로 브라우저의 React MessageChannel task 전달만 보류해, keyboard 해제의 URL 변경 뒤 중간 React commit 전 native Back을 결정적으로 실행했다. 전달이 실제 보류됐음을 확인하고 반드시 해제한 뒤 URL/표/메뉴·이후 목록의 선택과 F05/장바구니 저장값을 대조한다. 성공 응답을 바꾸거나 서버 지연·실제 자연 경쟁·성능을 측정한 것은 아니다.

같은 불변 spec의 빠른 이동 조건은 수정 전 실패1/1, 수정 후 실패0/1이다. 별도 정상 Back 대조는 전후 모두 실패0/1로 유지했다. 서로 다른 조건/횟수를 합쳐 운영 오류율이나 시간 성능으로 만들지 않는다. 기존 F06 전체 선택·해제·clear·URL/현재 값·개별 오류와 F05/카트의 전체 회귀도 수행한다.

독립 checkout은 별도 node_modules·보고서와 loopback61187을 사용한다. 기존 `npm run check` 전체를 그대로 실행하기 위해 Playwright의 숫자형 `PLAYWRIGHT_PORT`만 선택 가능하게 했다. 기본4173·strictPort·기존 필수 CI/보고서·자동 재시도 없음은 유지한다. 같은 outputDir의 runner를 겹쳐 실행하지 않는다.
