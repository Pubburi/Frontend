# F03 관리자 상품 특성 편집

## 범위·정본

- 기준 main: `a94346a7a4cb2d068e94af0582a5b6cd237e0c9d` (`#11`). 기존 관리자 상품 목록에 선택한 상품의 특성 편집을 추가한다. 기존 상품의 일곱 응답 필드와 생성·수정·삭제 API는 변경하지 않는다.
- 제공자 정본은 Backend의 [상품 특성 계약](https://github.com/Pubburi/Backend/blob/main/docs/PRODUCT-FEATURES.md)과 [OpenAPI 증가분](https://github.com/Pubburi/Backend/blob/main/docs/openapi/product-features.json)이다. 스키마/수집/학습의 상세 계획을 프론트에 복제하지 않는다.
- 이번 상태는 관리자 UI·API 소비·로컬 fixture 검증이다. 실제 Backend/MySQL의 화면→저장→재조회와 최신 PR/CI·리뷰·병합을 조정자가 확인하기 전 F03 전체 완료로 표시하지 않는다. 실검수 카탈로그·추천 모델 연결과 전체 FE03/C04도 별도다.

## 사용자 흐름·입력 의미

상품을 먼저 생성하고 목록의 **특성 편집**을 열어 별도 GET으로 현재 특성을 읽는다. 목록 전체에 상품별 추가 조회를 하지 않으며 초기 읽기에 실패하면 저장 폼을 열지 않고 명시적 재시도를 제공한다.

- 용량은 미입력 null 또는 1–1,000,000mL 정수다. 설명은 선택적 2,000자이며 빈칸을 unknown으로 보낸다. 현재 가격/도수/주종에서 용량·맛·향을 채우지 않는다.
- 맛·향은 각각 **미확인**, **검수 완료·선언할 태그 없음**, **확인한 태그 입력**을 선택한다. 세 상태를 각각 null, [], 문자열 배열로 전송한다. 한 줄 한 태그이며 종류별 최대 20개/각 40자·정규화 중복을 입력 경계에서 확인하고 서버 판단을 유지한다.
- 확인한 용량/설명 또는 non-null 태그(빈 배열 포함)에는 출처명이 필요하다. 선택적 URL은 계정 정보 없는 절대 HTTP(S)만 보낸다. 출처 기록이 이용 권리의 승인이 아니라는 안내와 sourceNote가 공개된다는 주의를 필요한 관리 화면에 표시한다.
- 저장은 일곱 값 전체를 PUT한다. **모두 미확인으로**는 현재 폼만 비우며 실제 저장은 다음 **특성 저장**에서 실행한다. 이때 모든 필드를 null로 보내 기존 특성/출처를 지운다. 기본 상품 가격/주종/도수·이미지·주문 수량을 수정하지 않는다.
- 성공 응답의 정규화된 태그/출처를 표시한다. 서버가 거절하면 성공으로 표시하거나 폼을 비우지 않는다. 읽기 실패를 빈 특성으로 간주해 덮어쓰지 않는다.

## 소유·오류 경계

선택한 상품/관리자 계정으로 query key와 편집 컴포넌트를 구분한다. 이전 GET의 늦은 결과/오류는 새 상품 폼에 적용하지 않는다. 저장은 상품별 동기 pending key로 중복 전송을 막고, 같은 상품의 닫기 후 재진입은 저장이 끝날 때까지 막아 이전 쓰기와 초기 조회의 경쟁을 피한다. 다른 상품은 독립적으로 편집할 수 있다.

제출한 불변 초안과 현재 초안이 동일할 때만 서버 정규화값으로 갱신한다. 저장 대기 중 계속 입력한 새 초안이나 다른 상품을 연 뒤의 초안을 이전 성공이 덮지 않는다. 성공 알림에 저장한 상품명을 표시하고 cache 갱신도 해당 상품에만 적용한다. 성공이 새 미저장 내용까지 저장했다는 의미는 아니다.

관리자 Guard와 서버 권한 검사를 유지한다. UI의 ADMIN 표시가 서버 승인을 대신하지 않으며, 403과 필드별 400 거절은 기존 ApiResponse 오류 안내로 표시한다. 공개 GET은 선택한 관리자 편집 폼의 초기 읽기로 소비하며 고객 화면에는 새 편집 컨트롤을 추가하지 않는다.

닫기/상품·탭 전환으로 떠난 미저장 폼을 영구 보관하지는 않는다. 서버 PUT은 기존 계약대로 revision/ETag가 없는 전체 교체이므로 다른 창/관리자의 동시 수정 충돌 해결을 제공하지 않는다. 전송 취소/시간 최적화·자동 수집/특성 추정도 이번 변경에 포함하지 않는다.

## 검증·근거

```bash
npm run typecheck
npm run test -- src/productFeatures.test.ts src/services/api.test.js
VITE_API_BASE_URL=/api npm run build
npm run test:browser -- --grep '특성'
npm run check
```

단위 검증은 null과 [] 구별·일곱 필드 전체 전송·정수 타입/범위·출처 필수·문자열 길이·태그 중복/개수·URL credential 거부·별도 credentialed GET/PUT 계약을 다룬다. 브라우저 검증은 다음 사용자 결과를 확인한다.

- 390px의 관리 화면에서 기존 미확인 읽기→빈 맛 태그/향 태그 입력·출처→저장/정규화→닫기/재조회→전체 지우기. 저장 전 출처 필수와 공개 메모 안내, 기본 상품 객체 불변과 포커스 복귀도 확인.
- 초기 GET 503은 저장 폼을 열지 않으며 재시도 뒤 복구. PUT 403과 필드 오류 400은 초안을 유지하고, 명시적 다음 저장만 실행.
- Promise gate로 상품 A GET을 보류하고 상품 B를 편집한 뒤 A 오류를 반환해도 B 초안/오류를 보호.
- A PUT을 보류한 동안 현재 폼에서 계속 입력하거나 상품 B로 이동해 새 초안을 작성해도 A 성공이 현재 입력을 덮지 않음. 제출 payload/횟수와 저장된 fixture는 원래 제출한 A만 반영.

선택 단위 12개·새 Chromium 5개 통과 후 최종 `npm run check`를 한 번 실행했다. Node 24.22.1에서 저장소 검사·locked 설치·audit 0·PNG/방향 JPEG 변환·strict TypeScript·단위 32개·프로덕션 빌드·Chromium 30개가 통과했다. 기존 브라우저 25개와 미처리 API/pageerror 검사도 유지했다. 이후 source 변경 없이 문서/인계만 정리하고 불변 dist SHA-256을 ignored 인계에 기록했다.

직접 작성한 검증 상품/태그는 실제 주류 특성·추천 학습 자료가 아니다. 새 기능 설계/계약 검증이므로 없는 과거 장애나 전후 성능 수치를 만들지 않았다. 실제 Backend/MySQL 통합과 혼동하지 않으며 그 추가 근거와 원격 PR/CI·리뷰·main 반영은 조정자가 관리한다.

## README 대표 사례 판단

미확인과 검수된 빈 태그의 구별·전체 교체 안전성·비동기 초안 소유는 의미 있는 새 제품 기능이다. 그러나 현재 자료는 신규 계약 설계와 fixture 검증이며, 기존 네 사례보다 더 큰 실제 문제/원인 규명·대안 비교·개선 효과를 입증한 독립 사례가 아니다. README에는 현재 기능만 추가하고 대표 사례 네 개/순서는 보존한다. 실검수 데이터와 검색/추천 연결에서 실제 문제를 발견·측정하면 다시 비교한다.
