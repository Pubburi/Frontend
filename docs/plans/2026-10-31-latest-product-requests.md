# 고객 상품 조회의 최신 요청 보존

이 문서는 Vue 유지 단계에서 재현·수정한 기록이다. 현재 React에서는 같은 게이트 시나리오를 유지하고 TanStack Query의 URL/상품/페이지 key가 응답을 격리한다. 구체적인 이전과 현재 경계는 [React 계획](2026-10-31-react-migration.md)을 따른다. 과거의 `runLatest` 코드가 현재 정본이라는 뜻은 아니다.

## 범위·원인

- 기준 커밋: `0e053fa8f35a5667fd82d6899014c8200932bc35`.
- 기존 Vue 고객 상품 목록·상세·후기 페이지 읽기만 변경한다. `/api`·ApiResponse·세션·정적 자산·쓰기의 중복 실행 차단을 유지한다. React 전환 시 보존해야 할 사용자 결과에도 포함한다.
- `ui.run`은 같은 키가 진행 중이면 action을 호출하지 않는다. URL query나 상세 화면이 바뀌어도 읽기 action이 누락되며, 기존 catalog는 응답 도착 순서대로 상태에 저장한다.
- 상세 action이 await 사이에 `route.params.id`를 다시 읽던 경계도 요청 시작 시 고정한 ID로 바꾼다.

## 수정 전 기준값·재현

실제 프로덕션 번들과 Chromium에서 직접 작성한 ApiResponse fixture를 사용했다. 실제 Backend·DB·외부 PG·실제 사용자 데이터는 사용하지 않았다. 응답은 시간값 대신 Promise gate로 보류해 순서를 통제했다. 같은 두 사용자 흐름을 수정 전후 비교한다.

| 시나리오 | 제어 조건·기대 결과 | 수정 전 관측 |
|---|---|---|
| 검색 진행 중 전체 해제 | 검색 A 응답을 보류 → 전체 해제로 URL B → B API/목록이 처리된 뒤 A 응답 반환 | URL에서 q가 사라져도 B API가 호출되지 않았다. 요청 누락 1/1 |
| 상세 A 진행 중 목록→상세 B | A 응답을 보류 → 목록으로 이동 → B 표시 → A의 503 반환 | B 상세가 표시되지 않았다. 최신 상세 표시 실패 1/1 |

수정 전 두 시나리오의 사용자 결과 위반은 **2/2**였다. 브라우저 회귀를 먼저 추가하고 기존 코드로 빌드·실행해 두 assertion 실패를 확인한 뒤 구현을 바꿨다. 최초 sandbox의 loopback EPERM은 실행 환경 제한으로 구분하고, 전용 preview/Chromium 실행 권한으로 재현했다. 기존 4173 서버를 재사용하거나 종료하지 않았다.

```bash
VITE_API_BASE_URL=/api npm run build
npm run test:browser -- --grep '진행 중 검색|상세 조회 중'
```

## 선택과 구현

- 쓰기용 `run`을 유지하고 읽기용 `runLatest`를 분리한다. 새로운 읽기를 즉시 실행하고 현재 버전일 때만 성공/오류 알림과 pending을 갱신한다. 이전 요청이 끝나도 최신 pending을 해제하지 않는다.
- store에 `isCurrent`를 전달해 실제 응답 적용 시점에도 검사한다. UI 오류만 숨기는 방식으로 데이터 덮어쓰기를 방치하지 않는다.
- 상품 목록/상세·후기 페이지에 적용하고 상세 이탈 때 읽기를 무효화한다. 검색 중에도 새 조건 제출을 허용한다.
- 단순 키 분리는 이전 요청의 늦은 상태 적용을 막지 못한다. 전송 취소만으로 적용 경계의 안전성을 대체하지 않고, 현재는 의존성 추가 없이 버전 검사로 동작을 보장한다. 이전 GET 전송 취소는 하지 않는다.

## 검증 결과·한계

수정 후 같은 두 게이트 시나리오의 결과 위반은 **0/2**였다. 감소는 재현한 정확성 오류의 결과이며 앱 로딩 지연·처리량 개선율이 아니다. 시험의 보류 응답을 실제 서비스 네트워크 지연 측정값으로 사용하지 않는다.

단위 검증은 늦은 성공의 catalog 덮어쓰기, 늦은 실패의 알림 오염, 이전 종료가 최신 pending을 지우는 문제, 댓글 페이지 역순 완료와 화면 이탈 무효화를 다룬다. 기존 쓰기 singleflight 검증도 유지한다. 전체 검증 명령은 `npm run check`이며 실제 결과는 PR/CI와 ignored 실행 기록에 남긴다.

이 변경은 모든 비동기 작업의 취소 계층이 아니다. 관리자 조회·세션 초기화의 통신 오류 구분·후기 쓰기 완료 후 재조회는 별도 경계다. 실제 서버 통합 E2E와 React 기능 동등성 완료를 대신하지 않는다. 공유 자원에서 전후 시간 성능을 측정하지 않았으며 지연 감소 수치를 주장하지 않는다.
