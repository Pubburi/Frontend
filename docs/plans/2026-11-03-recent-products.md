# F05 — 최근 본 상품의 로컬 보관과 인증 경계

## 범위·확정 보관 정책

기준 main `632977b`에서 2026-12-31 필수 MVP의 F05를 연결한다. 기존 공개 Product7 상세 GET과 현재 세션 계약으로 독립 실행하며 전체 P1·F02 엔진·PostgreSQL 전환 완료를 기다리지 않는다. 기준 화면의 기능 부재는 신규 기능 제공 전 상태이며 과거 장애·유출·시간 성능 개선으로 표현하지 않는다. 현재 완료 4/20(R01·F01·F03·F06)을 유지하고 F05 완료는 실제 인수·리뷰/CI·병합/main 확인 뒤 조정자가 판정한다.

2026-11-03에 다음 MVP 보관 범위를 확정했다. F05의 비회원/로그인 보관 범위 결정이며 계정 저장 API·기기 간 동기화를 약속하지 않는다.

## UI·API·소유 경계

- 공개 `/recent`와 주요 메뉴를 제공한다. 성공한 현재 상세 보기만 중복 없이 최근 순서로 추가하며 새 유효 재방문은 맨 앞으로 이동한다. 목록/비교 화면 자체를 상세 열람으로 기록하지 않는다.
- 상세 기록은 현재 인증 소유·location key에 속한다. 인증을 기다리다가 이탈한 상세나 인증 전환 중 연 상세, 이전 계정의 늦은 응답을 새 계정/비회원 기록으로 재귀속하지 않는다. 응답 완료로 포커스를 옮기지 않는다.
- 최근 경로는 현재 세션 확인 전 기록/카운트·상품 읽기를 노출하지 않는다. cached 세션의 현재401은 비회원으로 소유를 바꾸고,503은 실패/명시 확인으로 남겨 이전 기록을 가린다.
- 현재 기록의 ID만 `GET /api/products/{id}`로 재조회하고 응답 ID를 대조한다. 가격/도수·이름·이미지는 현재 Product7이며 스토리지의 상품/태그 스냅샷을 쓰지 않는다. 다시 연 상세의 기존 공개 특성 조회도 그대로 유지한다.
- 개별 삭제404·403/503·연결 대기·조회 실패를 다른 기록과 분리하고 명시 재시도/기록 삭제를 제공한다. cached 이전 상품을 현재 성공으로 표시하지 않는다. 전체 삭제는 로컬 기록만 비우며 업무 삭제 API를 호출하지 않는다.
- 엄격한 저장 형식·자료형·ID/시각·중복/최대20·크기 상한을 검사한다. 알 수 없는 버전/추가 snapshot 필드·손상 값은 복원하지 않으며, 만료/미래 기록도 조회하지 않는다.
- 기본 키보드 삭제/전체 삭제는 현재 집중된 버튼의 의도만 지속 제목으로 연결한다.390px 문서 너비와 화면 안내를 검증하고 기존 필터 URL·세션·F06 선택·장바구니/주문은 보존한다.

## 검증 계획과 실행 구분

제품 코드 전에 보관 정책과 현재 소유/GET·엄격 입력·기본 키보드·실제 인수 기준을 동결했다. 다음 직접 작성한 fixture는 실제 열람 로그·선호/추천 학습 자료가 아니다.

- 단위: ID/시각 전용 저장·20개/30일 정확 경계·중복 최신 이동, 조작/과다/미래/만료, 읽기/쓰기/삭제 거부의 메모리 보존·복구, 인증 bootstrap/503·pending·계정/ABA·분리된 옛 세션 결과.
- 브라우저: 실제 상세 선택·복원/삭제/전체 삭제, 현재 값·0·보관 안내, malformed snapshot 무조회, 인증 확인 전 디스크/상품 읽기 금지·이탈/늦은 로그인 소유, 회원 디스크0/새로고침 초기화·계정 전환·guest 삭제 거부 후 무재병합.
- 오류/입력: per-item404/403/503·응답 ID 불일치·명시 재시도, 제거 뒤 늦은 성공·cached/offline 재진입의 과거 값 비표시,390px Tab/Enter·포커스·가로 너비와 기존 F06/장바구니 보존.

최초 선택 브라우저의4건은 공통 상세 링크의 strict 선택자 범위와 인증 확인이 끝나기 전 행 배열을 즉시 읽던 작성 도구 전제였다. 원 spec/로그/trace를 보존하고 대상 상품 링크·현재 상세 응답과 행 readiness를 확인하도록 고쳤으며, 같은 제품 빌드에서17개가 통과했다. timeout/retry·skip·제품 상태 순서를 강제해 숨기지 않았다. 이후 추가한 bootstrap 이탈·응답 ID 경계와 저장 거부 검증은 전체 검사에서 확인한다.

[TESTING](../TESTING.md)의 기존 Node24 전체 검사를 수행한다. 실제 서버는 조정자 소유의 baseline/candidate 불변 production과 같은 하네스를 사용해 현재 Product7/특성 참조·비회원 직접 열람과 별도 작성 로컬 이력의20/30일 경계·없는 ID의 실제404·원문 장바구니2/F06·작성 계정의 실제 로그인/로그아웃·다른 계정/ABA를 확인한다. auth POST와 업무 쓰기, 제어 fixture와 실제 서버 관측·legacy/JPA/추천 연결 범위를 분리하며 원본 사용자/상품을 변경하지 않는다.

## 초기 미병합 후보의 인증 경계 보완

초기 후보의 전체 검사 통과 뒤 독립 읽기 검토에서 두 권위 경계를 추가 확인했다. 같은 `/recent`의 새 location key도 확인 소유에 포함해야 하며, 불확실한 인증 쓰기 실패 후 기존 success/idle 캐시만으로 기록을 재활성화하면 안 된다. 같은 링크 재진입1조건과 실패 logout/login503 fixture2조건·겹친 세션 읽기 단위1조건을 수정 전에 고정해 실패를 확인했다. 이는 이번 미병합 후보의 결함이며 과거 main/운영 사고나 자연 오류율이 아니다.

현재 검증은 location key+인증 세대에 묶고 새 진입부터 기록을 가린다. 인증 쓰기의 종료 뒤 시작한 실제 세션 읽기 성공만 불확실성 차폐를 해제하며, 그 전에 시작한 겹친 읽기나 수동 캐시 변경은 권위 확인으로 쓰지 않는다. 정상 인증의 새 query는 기존 흐름으로 받고, 추가 확인은 F05 화면에 국한해 전역 로그인/라우팅 정책을 확장하지 않았다. 알려진 소유는 확인 보류 중에도 상세 방문 시작에 결속해 나중에 확인된 다른 계정이 그 방문을 가져가지 못하게 했다. 이 마지막 소유 경계도 별도 fixture1조건을 먼저 재현했다.

처음 POP 도구는 같은URL 링크가 현재 entry를 replace한 뒤 Back하여 실제로 상세로 간 상태를 잘못 전제했다. URL만 바뀌고 목적 React 화면이 표시되기 전에 돌아간 시도도 분리 보존했다. 목적 카탈로그 화면 표시 후 native Back을 정상 대조로 확인하며, 이 준비 실패를 두 번째 인증 결함으로 합산하지 않는다. 같은 링크·실패 쓰기·방문 소유와 제어 fixture/실제 서버 결과의 분모도 서로 구분한다.
