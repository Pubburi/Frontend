# F11 부분 — 공개 매장 상세 연결

## 범위와 기준

기준 main `861fb07`에서 홈의 매장 이름·좌표는 조회되지만 고객용 상세 링크와 `/markets/:id` 화면은 없었다. 기존 공개 단건 계약을 소비해 홈/직접 주소에서 현재 매장을 확인하도록 연결한다. 이는 새 필수 기능의 일부 제공이며 기존 운영 장애나 성능 개선으로 표현하지 않는다. 현재 완료는 **6/20(R01·F01·F03·F05·F06·F09)**다. 이번 매장 상세만으로 데모 주문 보강·전체 F11/FE03/C04를 완료로 올리지 않는다.

제공자의 [API 계약](https://github.com/Pubburi/Backend/blob/main/docs/API-MAP.md)과 [매장 Controller](https://github.com/Pubburi/Backend/blob/main/src/main/java/com/pubburi/pub/controller/rest/MarketRestController.java)를 재사용한다. 새 업무 API·저장 정책·지도/외부 서비스를 만들지 않는다. 전체 PostgreSQL 전환 완료를 기다리는 대신 이미 제공된 legacy/JPA 계약을 별도로 검증한다.

- `GET /api/markets/{id}`의 ApiResponse `{id,name,latitude,longitude,image}`와200/404를 사용한다. 계정 선택/쓰기 없이 기존 credentials를 유지한다.
- 주소는 정규 양의 Java int만 허용한다. 0·음수·앞자리0·지수/소수 문법·상한 초과·반복 경로는 다른 ID로 변환하지 않고 단건 조회 없이 복구를 안내한다.
- 이름과 유한한 범위 내 좌표는 원문/숫자 값을 잘라내거나 반올림하지 않는다. 실제0과 null/비정상/범위 밖 값의 미확인을 구분한다. 주소·거리·영업시간·재고·예약 상태를 추정하지 않는다.
- 기존 이미지 필드는 있으나 현재 매장 사진 자산의 공급은 확인되지 않았다. 사진 미제공 상태를 안내하며 임의 사진·대역 이미지·외부 이미지 요청으로 채우지 않는다. 시연용 위치 정보임을 화면에 표시한다.

## 현재 요청·화면 소유

매장 ID별 Query key와 응답 ID 대조를 사용한다. 새 경로 key마다 조회 observer를 새로 열어 같은 ID 재진입도 현재 단건을 다시 확인한다. pending/paused/오류에서는 과거 성공의 이름·좌표를 현재 값으로 재노출하지 않는다. 이전 ID의 늦은 성공/실패는 현재 화면·포커스를 바꾸지 않는다.

404는 삭제/미제공 상태로,403/503은 조회 실패로 구분하고 홈 목록 또는 명시적 다시 확인을 제공한다. 공개 조회 실패를 비공개 계정 만료로 간주하지 않는다. 자동 재시도·오류의 재연결 재전송을 하지 않으며, 연결이 없어 시작하지 못한 읽기는 연결 후 재개한다. 새로고침/재시도 버튼은 대기 중에도 같은 DOM으로 유지하고 aria-disabled와 실행 guard로 중복을 막아 키보드 초점을 잃지 않는다. 완료 응답의 effect로 다른 조작의 초점을 옮기지 않는다.

현재 홈 목록은 기존 첫 페이지 범위를 유지한다. 전체 매장 목록/검색·지도·실제 매장 운영과 데모 주문의 추가 상세/상태 연결은 이 증분의 완료 범위가 아니다. F05의 계정/기기 보관, F06 URL 소유, F09 본인 수정·인증 쓰기 차폐와 기존 원문 장바구니 형식은 유지한다.

## 작성 검증의 실패와 정정

첫 선택 검사는12개 중11개를 통과했고, 상세에서 처음 홈으로 돌아간 직후 홈 조회가 준비되기 전에 offline을 주입한 도구 전제로 한 조건이 중단됐다. 원 spec/trace/로그를 보존하고 홈 상세 링크가 실제 준비된 뒤 offline을 시작하도록 바로잡았다. 제품 소스/빌드와 실제 GET 하네스는 바꾸지 않고 같은12개 조건을 모두 통과했다. 시간 초과·재시도·skip을 늘리지 않았다.

첫 전체 검사는 작성자가 원 Playwright spec을 테스트 확장자로 증거 디렉터리에 보관해 Vitest 수집이 실패했다. 실제 단위128개 성공과 수집 실패/전체 exit1을 구분하고 원 JUnit·로그를 보존했다. 사본 바이트를 유지한 보관 확장자로 옮겼으며 제품·검사 설정·회귀 assertion은 바꾸지 않았다. 이 도구 정정 뒤의 새 전체 결과로만 판정한다.
