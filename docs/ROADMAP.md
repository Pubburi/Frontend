# Frontend 구현·인수 계획

일정과 웹 기능 상태의 정본이다. 실행 이력·실험 원값·리뷰와 CI 결과는 Git/PR에서 관리한다.

전체 R01–R08·F01–F12의 MVP 구현·고객/관리 UI·API 연결·필수 실제 서버 인수 기한은 **2026-12-31 Asia/Seoul**이다. 현재 **9/20(R01·R06·F01·F03·F04·F05·F06·F09·F11)**을 완료했다. React 코드 이전(FE02)은 완료했으며 전체 고객/관리 인수(FE03/C04)와 PostgreSQL 전환은 진행 중이다. 부분 제공자·하위 결함 수정은 새 기능 완료로 합산하지 않는다.

## UX 기준

현재 ink/forest/gold/cream 테마에서 핵심 행동을 명확히 하고 불필요한 이동·반복 입력을 줄인다. 홈 직접 검색은 기존 F02 결과로 연결하며 빈 결과·오류에서도 입력을 보존해 수정/재시도로 이어진다. 기본 키보드·명확한 label·1280/390px 조작을 인수하고 기능 범위를 임의로 늘리지 않는다.

[NN/g](https://www.nngroup.com/articles/3-click-rule/)의 경로/상호작용 부담, [Baymard](https://baymard.com/research-articles/checkout-flow-average-form-fields)의 checkout 필드 부담, [토스](https://toss.tech/article/21023)의 가치가 명확한 행동, [스타벅스 공식 메뉴](https://www.starbucks.co.kr/menu/drink_list.do)의 분류 탐색을 참고한다. 임의 클릭 수 제한이나 다른 서비스의 성과 수치를 우리 성과로 사용하지 않는다.

## 남은 FE03/C04 인수

- [ ] 가입·중복 ID·로그인/로그아웃·세션 회수·계정 전환의 실제 성공/오류 조합.
- [ ] 고객 필터·정렬·페이지·배너·Back의 실제 화면 동등성.
- [ ] 후기 등록/수정/삭제·새 초안·실패와 장바구니/데모 주문·보관 제약·가격/삭제 이력의 전체 흐름.
- [ ] 취향·찜·관리자 상품/특성/매장/회원/후기/주문의 CRUD·권한 회수·오류 조합.
- [ ] 일반/390px의 키보드·스크린리더·시각 인수와 세 서버/목표 DB의 장애·복구 통합.

각 기능은 로딩·빈 값·오류·명시 복구, 최신 요청/초안·중복 쓰기·계정 격리를 포함해 인수한다. [TESTING](TESTING.md)의 필수 검사를 유지하고 fixture·실제 통합·모델 품질의 근거를 구분한다. 현재 README의 네 사례는 [선정표](case-study-register.md)를 따르며 새 실행마다 설명을 덧붙이지 않는다.
